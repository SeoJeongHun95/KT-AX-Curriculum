# 요구사항 문서 — 고객센터 메일 답장 워크플로우

- 기능 또는 조건 1건을 1행으로 적습니다.
- 각 행은 목적·사용자·입출력 예시·도구·완료 기준의 다섯 칸을 모두 채웁니다.
- 완료 기준은 코드가 참·거짓으로 판정할 수 있는 문장으로 적습니다.

| # | 기능 / 조건 | 목적 | 사용자 | 입출력 예시 | 도구 | 완료 기준 |
|---|---|---|---|---|---|---|
| R1 | 메일 종류 분류 | 담당자가 메일을 읽고 종류를 판단하는 반복 작업을 없앤다 | 고객센터 메일 담당자 | 입력: `"주문한 신발이 아직 안 왔습니다. 주문번호 A-1021입니다."` / 출력: `category="배송"` | LangGraph 노드 · LLM 호출(구조화 출력) | 환불·배송·스팸 예시 메일을 각각 넣었을 때 `category` 값이 세 단어 중 하나로만 채워진다 |
| R2 | 스팸 메일 즉시 종료 | 광고 메일에 답장을 쓰는 비용과 오발송 위험을 없앤다 | 고객센터 메일 담당자 | 입력: `category="스팸"` / 출력: 답장 없이 종료, 종료 사유 `"스팸으로 분류되어 답장을 만들지 않았습니다."` | LangGraph 조건부 엣지 | 광고 메일을 넣으면 실행 기록에 답장 작성 노드가 나타나지 않는다 |
| R3 | 답장 초안 작성 | 담당자가 초안을 직접 쓰는 작업을 없앤다 | 고객센터 메일 담당자 | 입력: 메일 본문과 `category="환불"` / 출력: `draft="주문번호 A-1021 환불 요청을 접수했습니다. 3영업일 안에 환불 처리 결과를 회신드립니다."` | LangGraph 노드 · LLM 호출 | 환불 문의를 넣으면 `draft` 칸이 빈 문자열이 아닌 값으로 채워진다 |
| R4 | 초안 검사 | 주문번호와 처리 기한이 빠진 답장이 고객에게 나가는 일을 막는다 | 고객센터 팀장 | 입력: 메일 본문과 `draft` / 출력: `review="합격"` 또는 `review="반려"`와 `reject_reason="주문번호가 들어 있지 않습니다."` | LangGraph 노드 · LLM 호출(구조화 출력) | 주문번호를 뺀 초안을 넣으면 `review` 값이 `"반려"`가 되고 `reject_reason` 칸이 채워진다 |
| R5 | 반려 시 재작성 | 검사에서 지적된 항목을 반영한 답장을 만든다 | 고객센터 메일 담당자 | 입력: `reject_reason="주문번호가 들어 있지 않습니다."` / 출력: 주문번호가 들어간 새 `draft` | LangGraph 조건부 엣지(되돌림) | 반려된 초안이 다시 작성되어 두 번째 검사에서 `review="합격"`이 되는 실행 기록이 남는다 |
| R6 | 재작성 횟수 상한 | 검사와 재작성이 끝나지 않고 되풀이되는 상태를 막는다 | 고객센터 팀장 | 입력: `attempt=3` / 출력: 발송하지 않고 `status="담당자 확인 필요"` | LangGraph 조건부 엣지 · 상태 칸 `attempt` | 항상 반려를 돌려주는 검사로 실행하면 초안 작성 노드가 3회까지만 실행되고 워크플로우가 종료된다 |
| R7 | 발송과 기록 | 발송한 답장과 발송하지 않은 사유를 담당자가 확인할 수 있게 한다 | 고객센터 메일 담당자 | 입력: 합격한 `draft` / 출력: 화면에 발송 내용 출력, `sent=True` | LangGraph 노드 · 화면 출력 | 실행이 끝난 뒤 `sent` 값과 발송 본문 또는 종료 사유가 화면에 출력된다 |
