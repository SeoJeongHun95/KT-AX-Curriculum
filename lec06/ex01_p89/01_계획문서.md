# 계획 문서 — 고객센터 메일 답장 워크플로우

작성자: 강사 · 작성일: 2026-09-03 · 대상 시스템: 고객센터 메일 분류·답장 워크플로우

---

## 1. 문제상황

- **누가 겪는가**: 온라인 쇼핑몰 고객센터의 메일 담당자가 겪습니다.
- **지금 어떻게 하고 있는가**:
  1. 담당자는 고객센터 메일함에 들어온 메일을 열어 봅니다.
  2. 담당자는 메일을 읽고 환불 문의인지, 배송 문의인지, 광고 메일인지를 눈으로 판단합니다.
  3. 담당자는 광고 메일을 삭제하고, 환불 문의와 배송 문의에는 답장 초안을 직접 씁니다.
  4. 담당자는 초안을 다시 읽고 주문번호와 처리 기한이 들어 있는지 확인한 뒤 발송합니다.
- **무엇이 불편한가**:
  - 담당자는 메일 수만큼 판단과 작성을 반복합니다. 메일이 늘어나면 담당자의 작업 시간이 같은 비율로 늘어납니다.
  - 담당자는 초안을 급하게 쓸 때 주문번호나 처리 기한을 빠뜨립니다. 빠뜨린 답장이 고객에게 나가면 고객이 같은 내용을 다시 문의하고, 담당자의 일이 한 번 더 발생합니다.
  - 담당자마다 답장에 담는 항목이 다릅니다. 고객이 받는 답장의 내용이 담당자에 따라 달라집니다.

## 2. 목표

- **입력**: 고객센터 메일 본문 문자열입니다.
- **출력**: 메일 종류(환불·배송·스팸)와 발송된 답장 본문입니다. 스팸으로 분류된 메일에 대해서는 답장을 만들지 않고 종료 사유를 출력합니다.
- **달성 조건**:
  1. 환불 문의 메일을 입력하면 워크플로우가 종류를 환불로 판정하고, 주문번호와 처리 기한이 모두 들어 있는 답장을 발송합니다.
  2. 광고 메일을 입력하면 워크플로우가 종류를 스팸으로 판정하고, 답장을 만들지 않은 채 종료합니다.
  3. 주문번호가 빠진 초안이 만들어진 경우, 워크플로우가 초안을 발송하지 않고 반려 사유를 붙여 다시 작성하게 합니다.
  4. 다시 작성을 되풀이하는 횟수에 상한이 있고, 상한에 도달하면 워크플로우가 발송을 중단하고 담당자 확인 대상으로 표시합니다.

## 3. 개발 절차 계획

| 순서 | 산출물 | 이 단계에서 하는 일 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| 1 | 요구사항 문서(`02_요구사항문서.md`) | 목표를 달성하는 데 필요한 기능과 조건을 1건씩 행으로 적고, 각 행에 목적·사용자·입출력 예시·도구·완료 기준을 채운다 | 모든 행의 완료 기준이 참·거짓으로 판정 가능한 문장이다 |
| 2 | 아키텍처 다이어그램(`03_아키텍처다이어그램.md`) | 요구사항을 노드와 엣지로 배치하고, 노드마다 입력·책임·출력·상태·제약·경계를 적는다 | 요구사항 문서의 모든 행이 다이어그램의 노드 또는 엣지에 대응한다 |
| 3 | 의사결정 기록(`04_의사결정기록.md`) | 2단계에서 갈린 판단을 문제/맥락·선택지·판단 기준·결정·근거·결과/대가·재검토 조건으로 남긴다 | 선택지가 둘 이상이었던 판단이 모두 기록되어 있다 |
| 4 | 코드 | 다이어그램의 노드를 함수로, 엣지를 그래프 연결로 옮긴다 | 요구사항 문서의 완료 기준을 실행 기록으로 확인한다 |

- **앞 단계로 되돌아가는 조건**:
  - 2단계에서 노드에 적을 입력이나 출력이 정해지지 않으면 1단계로 돌아가 요구사항 행을 고칩니다.
  - 3단계에서 판단 기준을 적을 수 없으면 2단계로 돌아가 노드 배치를 다시 봅니다.
  - 4단계에서 완료 기준을 만족하지 못하면 1단계의 완료 기준이 실제로 측정 가능한지부터 다시 봅니다.

## 4. 범위에서 제외하는 것

- 메일함에서 메일을 가져오는 연동은 만들지 않습니다. 메일 본문 문자열을 직접 넣습니다.
- 실제 발송은 하지 않습니다. 발송은 화면 출력으로 대신합니다.
- 고객 개인정보 저장은 하지 않습니다. 메일 본문은 실행이 끝나면 남기지 않습니다.
