Agentic AI (2026.09.07 ~ 09.22) · 강사 김정훈 버전 확인일 2026-09-03

0. 개강 전 설치 권고 5종

아래 5개를 미리 설치해 오시면 1일차가 훨씬 빨라집니다. 이미 설치해 오셨다면 1장의 해당 단계는 건너뛰시면 됩니다.

프로그램 받는 곳 설치 후 확인 명령 기대 결과
Anaconda https://www.anaconda.com/download conda --version conda 2x.x.x 형태의 버전이 출력됩니다
Git for Windows https://git-scm.com/download/win git --version git version 2.x.x 가 출력됩니다
Visual Studio Code https://code.visualstudio.com code --version 버전 번호 3줄이 출력됩니다
Claude Code https://claude.com/product/claude-code claude --version 버전 번호가 출력됩니다
Google Antigravity https://antigravity.google 프로그램이 실행되면 됩니다 창이 열립니다
  • 확인 명령은 모두 PowerShell에서 실행합니다 (1장 1단계 참고).
  • 확인 명령이 "인식할 수 없습니다"라고 나오면, 설치 자체는 됐어도 터미널이 아직 모르는 상태입니다. 터미널 창을 닫고 새로 여신 뒤 다시 실행해 주십시오.
  • Docker는 이 과정에서 설치하지 않습니다. 설치하지 마십시오.

1. 1일차 — 함께 합니다

1일차 수업 중에 강사와 같이 진행합니다. 미리 혼자 다 하실 필요는 없습니다. 각 단계 끝의 [확인] 명령이 성공해야 다음 단계로 넘어갑니다. 실패하면 멈추고 손을 들어 주십시오.

1단계 — PowerShell 열기

  • Windows 시작 메뉴에서 PowerShell을 검색해 Windows PowerShell을 엽니다.

[확인]

$PSVersionTable.PSVersion
  • 버전 표가 출력되면 성공입니다.

2단계 — uv 설치

uv는 파이썬 패키지를 설치하고 실습용 파이썬 환경을 만들어 주는 도구입니다.

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

설치가 끝나면 PowerShell 창을 닫고 새 창을 엽니다. (이 단계를 건너뛰면 다음 확인 명령이 반드시 실패합니다.)

[확인]

uv --version
  • uv 0.12.x 형태가 출력되면 성공입니다.
  • 실패 시: 새 터미널을 열지 않았을 가능성이 가장 큽니다. 창을 다시 닫고 열어 재시도하십시오. 그래도 안 되면 손을 들어 주십시오. pip install uv로는 설치하지 마십시오.
  • 새 창에서도 uv가 인식되지 않으면: uv도 C:\Users\{본인 폴더}\.local\bin에 설치되므로, 8단계 「실패 시 ①」과 같은 방법으로 그 경로를 사용자 Path에 추가하고 PowerShell을 다시 엽니다.

3단계 — Git for Windows 설치

Git은 코드의 변경 이력을 남기는 도구이며, Claude Code가 내부적으로 사용하기도 합니다.

  • https://git-scm.com/download/win 에서 64-bit 설치 파일을 받습니다.
  • 설치 마법사의 모든 화면에서 기본값 그대로 [Next] 를 누르고 마지막에 [Install]을 누릅니다. 옵션을 바꿀 필요가 없습니다.
  • 설치가 끝나면 PowerShell 창을 닫고 새로 엽니다.

[확인]

git --version
  • git version 2.x.x가 출력되면 성공입니다.
  • 실패 시: 터미널을 껐다가 다시 켜서 확인해보세요.

4단계 — VS Code 설치 + 확장 2개

  • https://code.visualstudio.com 에서 설치 파일을 받아 설치합니다. 설치 화면 중 "Add to PATH" 항목은 체크된 상태로 두십시오.
  • VS Code를 실행한 뒤 왼쪽 세로 막대에서 네모 4개 모양(확장, Extensions) 아이콘을 누릅니다.
  • 검색창에 Python을 입력하고, 게시자가 Microsoft인 Python 확장을 설치합니다.
  • 같은 방법으로 Jupyter를 검색해 Microsoft의 Jupyter 확장을 설치합니다.

[확인]

code --version
  • 버전 번호가 출력되고, VS Code 확장 목록에 Python·Jupyter 두 개가 보이면 성공입니다.
  • 실패 시: 새 터미널을 열고 재시도하십시오.

5단계 — 실습 폴더 만들고 패키지 설치

실습 폴더 agentic-ai는 여러분이 두고 싶은 곳에 만듭니다. 단, 아래 세 가지를 지킵니다.

  • 위치를 먼저 정한 뒤 설치합니다. 설치가 끝난 폴더를 다른 곳으로 옮기면 환경이 깨집니다. 옮겼다면 옮긴 폴더에서 uv sync를 다시 실행합니다.
  • 바탕화면·문서 폴더에는 만들지 않습니다. OneDrive가 동기화하는 폴더라 설치가 느려지거나 파일 잠금 오류가 납니다.
  • 폴더 경로에 한글이 들어가지 않게 합니다. Windows 사용자 이름이 한글이면 C:\Users\... 아래가 아니라 C:\agentic-ai처럼 드라이브 바로 아래에 만듭니다.

아래는 C:\agentic-ai에 만드는 예입니다. 다른 위치에 만들었다면 이후 명령의 경로도 그 위치로 바꿉니다.

mkdir C:\agentic-ai
cd C:\agentic-ai
  • 강사가 배포한 pyproject.toml, uv.lock, .env.example 세 파일을 방금 만든 agentic-ai 폴더 안에 넣습니다.
  • 세 파일이 폴더 안에 있는지 확인합니다.
dir
  • 세 파일이 보이면, 아래 한 줄로 실습에 필요한 파이썬 패키지를 전부 설치합니다.
uv sync
  • 처음 실행하면 파이썬 3.13을 내려받고 패키지 200여 개를 설치하므로 수 분이 걸립니다. 중간에 창을 닫지 마십시오.
  • 끝나면 폴더 안에 .venv 라는 폴더가 새로 생깁니다. 이 .venv 폴더가 이 과정 내내 쓰는 파이썬 환경입니다.

[확인]

.\.venv\Scripts\python.exe -c "import langgraph, langchain, langchain_litellm, litellm, fastapi, chromadb, mcp, langsmith, jupyterlab; print('ok')"
  • ok 한 줄이 출력되면 성공입니다.
  • 실패 시: 네트워크 문제라면 uv sync를 한 번 더 실행하면 이어서 받습니다. 다른 오류면 오류 전문을 그대로 보여 주십시오.

6단계 — VS Code 인터프리터 지정하고 노트북 실행

  • VS Code에서 [파일] → [폴더 열기]로 agentic-ai 폴더를 엽니다.
  • Ctrl+Shift+P → Python: Select Interpreter 입력 → 목록에서 경로가 .venv 로 시작하거나 ('.venv')가 붙은 항목을 선택합니다.
  • 강사가 배포한 노트북(.ipynb) 파일을 열고, 오른쪽 위 커널 선택에서 같은 .venv를 고릅니다.
  • 첫 번째 셀을 실행합니다 (셀 왼쪽의 재생 버튼 또는 Shift+Enter).

[확인]

  • 셀 왼쪽에 실행 번호 [1]이 뜨고 오류가 없으면 성공입니다.
  • 실패 시: 인터프리터가 .venv가 아니라 아나콘다(base)로 잡혀 있는 경우가 대부분입니다. 다시 선택하십시오.

7단계 — .env 파일 만들기

API 키처럼 남에게 보이면 안 되는 값을 담는 파일입니다. agentic-ai 폴더의 맨 위(최상단)에 하나만 만듭니다.

cd C:\agentic-ai
Copy-Item .env.example .env
notepad .env

  • C:\agentic-ai는 5단계의 예시 경로입니다. 실습 폴더를 다른 위치에 만들었다면 그 경로로 이동합니다.

  • 메모장이 열리면 OPENAI_API_KEY= 뒤에 강사가 개인별로 나눠 주는 키를 붙여넣고 저장합니다.

  • 키는 1일차에 강사가 직접 안내합니다. 미리 구하실 필요 없습니다.

[확인]

.\.venv\Scripts\python.exe -c "from dotenv import load_dotenv, find_dotenv; import os; load_dotenv(find_dotenv(usecwd=True)); print(bool(os.getenv('OPENAI_API_KEY')))"
  • True가 출력되면 성공입니다.
  • 실패 시: 파일 이름이 .env.txt로 저장됐을 수 있습니다. dir .env* 로 이름을 확인하십시오.

8단계 — Claude Code 설치와 로그인

irm https://claude.ai/install.ps1 | iex
  • 설치가 끝나면 PowerShell 창을 닫고 새로 엽니다.
  • 새 창에서 실습 폴더(agentic-ai)로 이동해 실행하고, 안내에 따라 본인 계정으로 로그인합니다.
cd C:\agentic-ai
claude
  • C:\agentic-ai는 5단계의 예시 경로입니다. 실습 폴더를 다른 위치에 만들었다면 그 경로로 이동합니다.

[확인]

claude doctor
  • 설치 상태 점검 결과가 출력되면 성공입니다.
  • 실패 시 ① — 아래와 같은 오류가 나오면 PATH(환경 변수) 문제입니다.
PS> claude --version
claude : 'claude' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다. ...
    + CategoryInfo          : ObjectNotFound: (claude:String) [], CommandNotFoundException
    + FullyQualifiedErrorId : CommandNotFoundException

다음 순서로 경로를 직접 추가합니다.

  1. 윈도우 시작 메뉴에서 「시스템 환경 변수 편집」을 실행합니다.
  2. 「환경 변수」 버튼을 누릅니다.
  3. 위쪽 「사용자 변수」 목록에서 Path를 선택하고 「편집」을 누릅니다.
  4. 「새로 만들기」를 누르고 C:\Users\{본인 폴더}\.local\bin 을 입력합니다. {본인 폴더} 대신 본인의 윈도우 사용자 폴더 이름을 넣습니다. 폴더 이름은 PowerShell에서 echo $HOME 으로 확인할 수 있습니다.
  5. 「확인」을 세 번 눌러 창을 모두 닫습니다.
  6. PowerShell 창을 닫고 새로 엽니다. 그 뒤 claude --version 을 다시 실행합니다.

3. 자주 나오는 문제

증상 원인 해결
uv, git, claude, node 가 "인식할 수 없습니다"로 나옴 설치 직후 터미널이 아직 새 경로를 모름 PowerShell 창을 닫고 새로 엽니다. 그래도 안 되면 PC를 재부팅합니다
새 창에서도 claude 가 "인식되지 않습니다"(CommandNotFoundException)로 나옴 설치 폴더가 사용자 Path에 등록되지 않음 「시스템 환경 변수 편집」 → 환경 변수 → 사용자 변수 Path → 새로 만들기 → C:\Users\{본인 폴더}\.local\bin 추가 → 확인 → PowerShell 재실행 (8단계 「실패 시 ①」에 단계별 순서가 있습니다)
설치 스크립트가 "이 시스템에서 스크립트를 실행할 수 없습니다"로 막힘 PowerShell 실행 정책 명령 앞에 powershell -ExecutionPolicy ByPass -c "..." 형태를 그대로 사용합니다 (2단계 명령이 이미 그 형태입니다)
uv sync 가 중간에 끊김 / 다운로드 실패 네트워크 일시 문제 같은 폴더에서 uv sync를 다시 실행하면 받은 데까지는 재사용합니다. 2~3회 재시도
노트북 셀 실행 시 ModuleNotFoundError VS Code가 .venv가 아닌 다른 파이썬을 쓰고 있음 Ctrl+Shift+P → Python: Select Interpreter → .venv 선택. 노트북 오른쪽 위 커널도 .venv로 변경
fastapi dev 가 "명령을 찾을 수 없습니다" 서버 실행 도구가 빠진 상태 배포된 pyproject.toml·uv.lock을 그대로 쓰고 uv sync를 다시 실행합니다 (fastapi[standard]가 들어 있어야 합니다)
.env 를 만들었는데 키를 못 읽음 파일이 .env.txt로 저장됨 / 실습 폴더 최상단이 아닌 곳에 있음 dir .env* 로 이름 확인, 파일은 실습 폴더 맨 위에 하나만 둡니다
한글이 들어간 명령을 터미널에 직접 붙여넣으면 글자가 깨짐 윈도우 터미널 인코딩 한글이 들어간 내용은 터미널에 직접 치지 말고 UTF-8 파일로 저장해서 사용합니다
